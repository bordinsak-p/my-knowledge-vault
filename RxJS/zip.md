# 🤐 zip — จับคู่ค่าตามลำดับที่มาถึง

> `zip` จับคู่ค่าจากหลาย Observable **ตามลำดับที่ปล่อยออกมา** — ค่าที่ 1 ของ source A คู่กับค่าที่ 1 ของ source B, ค่าที่ 2 คู่กับค่าที่ 2 เสมอ ไม่ว่าตัวไหนจะมาถึงก่อนก็ตาม `zip` **รอให้ครบคู่ก่อนถึงจะปล่อยออกไป**

---

## ตัวอย่าง — UI action: เปิดข้อความ onboarding ทีละอันตามจังหวะที่ผู้ใช้กด "ถัดไป"

```ts
const tooltipMessages = ['ยินดีต้อนรับ!', 'นี่คือเมนูหลัก', 'กดตรงนี้เพื่อเริ่มงาน'];

zip(nextButtonClicks$, from(tooltipMessages)).pipe(
  map(([, message]) => message),
).subscribe(message => this.showTooltip(message));
```

ผู้ใช้กด "ถัดไป" ครั้งที่ 1 → ได้ข้อความที่ 1, กดครั้งที่ 2 → ได้ข้อความที่ 2 เรียงตามลำดับเป๊ะ — ถ้าผู้ใช้กดเร็วกว่าที่มีข้อความเหลือ `zip` จะหยุดเองเมื่อ source ใดหมดก่อน (ในที่นี้คือ array ข้อความหมดก่อน)

---

## ต่างจาก [[combineLatest]] ชัดเจนที่สุดตรงนี้

```ts
// zip — จับคู่ตามลำดับ ("ตัวที่ 1 คู่กับตัวที่ 1")
zip(source1$, source2$)   // (1st,1st), (2nd,2nd), (3rd,3rd), ...

// combineLatest — จับคู่ค่าล่าสุด ณ ขณะนั้น ("ล่าสุดของทั้งคู่")
combineLatest([source1$, source2$])   // ยิงใหม่ทุกครั้งที่ตัวใดตัวหนึ่งเปลี่ยน ไม่สนว่าเป็นค่าลำดับที่เท่าไหร่
```

`zip` สนใจ**ลำดับที่มาถึง** (position-based) ส่วน `combineLatest` สนใจแค่**ค่าล่าสุด ณ ตอนนั้น** (time-based) — สองแนวคิดต่างกันโดยสิ้นเชิงแม้หน้าตาการเรียกจะคล้ายกัน

---

## เทียบกับ [[forkJoin]] และ [[combineLatest]]

| operator | ยิงค่าออกมาตอนไหน | เหมาะกับ |
|---|---|---|
| **zip** | จับคู่ตามลำดับ (ค่าที่ 1 คู่กับค่าที่ 1, ค่าที่ 2 คู่กับค่าที่ 2 ...) | ต้องเรียงคู่ค่าจากหลาย source ให้ตรงกันตามลำดับ |
| [[forkJoin]] | รอทุกตัว **complete** แล้วยิงครั้งเดียว (ค่าสุดท้ายของแต่ละตัว) | เรียก API หลายตัวพร้อมกัน รอครบทุกตัว |
| [[combineLatest]] | ยิงทุกครั้งที่ตัวใดตัวหนึ่งปล่อยค่าใหม่ (หลังทุกตัวปล่อยค่าแรกแล้ว) | ค่าที่ derive จากหลาย stream ที่ยังเปลี่ยนต่อเนื่อง |

---

## กับดัก

- **ใช้ `zip` ทั้งที่จริง ๆ ต้องการแค่ "ค่าล่าสุด"** — สับสนกับ `combineLatest` เพราะหน้าตาการเรียกคล้ายกันมาก แต่ความหมายต่างกันคนละเรื่อง (ดูด้านบน)
- **source หนึ่งเร็วกว่าอีกตัวมาก** — `zip` จะสะสมค่าที่ยังไม่มีคู่ไว้ใน buffer รอเรื่อย ๆ ถ้า source เร็วไม่จับคู่ทัน อาจกิน memory สะสมโดยไม่รู้ตัว
- **คาดหวังว่า `zip` จะทำงานต่อได้แม้ source หนึ่งหมดไปแล้ว** — พอ source ไหน complete ก่อน `zip` ทั้งก้อนจะ complete ตามทันที (ตัดคู่ที่เหลือของอีกฝั่งทิ้งไปเลย ไม่ปล่อยออกมา)
