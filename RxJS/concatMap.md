# 🔀 concatMap — เข้าคิว ทีละตัวตามลำดับ

> `concatMap` คือ flattening operator ที่ **เข้าคิวรอ** — inner Observable ตัวใหม่จะเริ่มทำงานก็ต่อเมื่อตัวก่อนหน้า **complete แล้วเท่านั้น** เหมาะกับงานที่ **ต้องการลำดับแน่นอน** ห้ามสลับกัน

---

## ตัวอย่าง — API call: บันทึกหลายรายการที่ต้องเรียงลำดับ

```ts
saveQueue$.pipe(
  concatMap(item => this.http.post('/api/items', item)),
).subscribe();
```

ถ้าใช้ [[mergeMap]] แทน รายการที่ 2 อาจถูกบันทึกเสร็จก่อนรายการที่ 1 ด้วยซ้ำ (ยิงพร้อมกัน ใครเสร็จก่อนก็ก่อน) — `concatMap` การันตีว่ารายการที่ 2 จะ**เริ่มยิง** ก็ต่อเมื่อรายการที่ 1 เสร็จสมบูรณ์แล้วเท่านั้น รักษาลำดับได้แน่นอน 100%

---

## เทียบกับ flattening operator ตัวอื่น

| operator | ตัวใหม่เข้ามาก่อนตัวเก่าเสร็จ ทำยังไง |
|---|---|
| **concatMap** | เข้าคิวรอตัวเก่าเสร็จก่อน |
| [[switchMap]] | ยกเลิกตัวเก่าทันที สลับไปตัวใหม่ |
| [[mergeMap]] | ปล่อยให้ทำงานพร้อมกันทั้งคู่ |
| [[exhaustMap]] | เมินตัวใหม่ทิ้งไปเลย |

---

## กับดัก

- **ใช้ `concatMap` กับ source ที่ยิงถี่มากและแต่ละตัวไม่เกี่ยวกัน** — งานที่ไม่จำเป็นต้องเรียงลำดับแต่ใช้ `concatMap` ทำให้ช้าลงโดยไม่จำเป็น (ตัวหลังต้องรอตัวก่อนเสร็จเสมอ) ทั้งที่ยิงพร้อมกันได้จริงด้วย [[mergeMap]]
- **คิดว่า `concatMap` เร็วเท่า `mergeMap`** — ไม่จริง `concatMap` ช้ากว่าเสมอเมื่อมีหลายตัวค้างคิว เพราะรอทีละตัว ต้องยอมรับ trade-off นี้เพื่อแลกกับการรักษาลำดับ
- **queue ยาวมากจนผู้ใช้รอนาน** — ถ้า source ยิงเร็วกว่าที่ inner Observable แต่ละตัวจะเสร็จ คิวจะพอกพูนขึ้นเรื่อย ๆ ควรพิจารณาจำกัดจำนวนหรือแจ้งสถานะคิวให้ผู้ใช้เห็น

---

## Cheat sheet

```ts
source$.pipe(concatMap(value => innerObservable(value)))
```
