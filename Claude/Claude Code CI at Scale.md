# 📈 Agentic Coding กับ CI — เคสจริงที่ Anthropic ต้องปรับระบบตัวเอง

> Case study จาก Anthropic เอง — เมื่อ agentic coding ทำให้ปริมาณโค้ดที่เขียนเพิ่มขึ้นมหาศาล ระบบ CI เดิมที่เคยพอใช้ได้เริ่มรับไม่ไหว

---

## 1. ตัวเลขที่เกิดขึ้นจริง

- วิศวกร Anthropic ส่งโค้ดเฉลี่ย **8 เท่า** ต่อไตรมาส เทียบกับช่วงปี 2021-2025
- **Claude เป็นคนเขียนโค้ดถึง 80%** ของทั้งหมดนั้น (รวมช่วยรีวิว/อนุมัติ PR ด้วย)
- CI job เพิ่มขึ้น **25 เท่า** ภายใน 6 เดือน
- ปริมาณเทสทั้ง codebase เพิ่มขึ้น **10 เท่า**

การเติบโตขนาดนี้เกือบทำให้ระบบ **test impact analysis** (ตัดสินใจว่า PR หนึ่งควรรันเทสไหนบ้าง ไม่ต้องรันทั้งหมดทุกครั้ง) ล่มไปเลย

---

## 2. ทางแก้ที่ค่อยๆ พังทีละรอบ ก่อนจะแก้ถูกจุด

ระบบเดิมเป็นสถาปัตยกรรมแบบ singleton (instance เดียว) — สเกลแนวนอน (horizontal) ไม่ได้ ต้องแพตช์ต่อเนื่อง:

| รอบ | วิธีแก้ | อยู่ได้นาน |
|---|---|---|
| แพตช์ 1 | เพิ่ม core ของเครื่องเป็น 2 เท่า | 70 วัน |
| แพตช์ 2 | แบ่ง sharding ตาม package | 29 วัน |
| แพตช์ 3 | restart ระบบทุกวัน | < 1 วัน |

**แต่ละรอบซื้อเวลาได้น้อยลงเรื่อยๆ** — สัญญาณชัดว่าต้องแก้ที่สถาปัตยกรรม ไม่ใช่แพตช์ไปเรื่อยๆ

---

## 3. ทางแก้จริง — ทำให้ stateless แล้วสเกลแนวนอนได้

ออกแบบใหม่โดยใส่ **in-memory data store** เข้าไป ทำให้ส่วน "listener" (บันทึกผลเทส) กลายเป็น **stateless** สเกลแนวนอนได้จริง ไม่ติดคอขวดที่ instance เดียวอีกต่อไป

> **"โปรเจกต์นี้ใช้เวลาวิศวกรคนเดียว 3 สัปดาห์ เมื่อปีที่แล้วคงต้องใช้เวลาเกือบหนึ่งไตรมาส"**

---

## 4. ข้อคิดสำคัญ

**วางแผนรับการเติบโตแบบ exponential ไว้ตั้งแต่ต้น ไม่ใช่แค่ scale แบบค่อยเป็นค่อยไป** — agentic coding เปลี่ยนสมการของ infrastructure demand ไปจริงๆ ไม่ใช่แค่ "เขียนโค้ดเร็วขึ้นนิดหน่อย" การเตรียม CI/infra ให้รองรับการเติบโตแบบก้าวกระโดดสำคัญพอๆ กับการเตรียม code quality
