# 🐳 Docker — จากศูนย์ถึง deploy เอง

หน้ารวมโน้ต Docker — เขียนไว้สำหรับคนที่**ไม่เคยใช้ Docker มาก่อนเลย** ไม่ต้องมีพื้นฐาน
เรียงเป็น 3 ภาค อ่านและทำตามตามลำดับ แต่ละภาคมี step ให้ลงมือทำจริง ไม่ใช่แค่อ่านทฤษฎี

> **สภาพแวดล้อม:** เขียนโดยอ้างอิง **Windows 11 + Docker Desktop (WSL2 backend)** เพราะเป็นเครื่องที่ใช้งานอยู่
> คำสั่ง `docker` เองเหมือนกันทุก OS ต่างกันแค่ขั้นตอนติดตั้ง

## เส้นทางการเรียน — ทำตามลำดับ

| ภาค | โน้ต | ได้อะไร | สถานะ |
|---|---|---|---|
| **1** | [[Docker Basics]] | เข้าใจว่า image/container คืออะไร, ติดตั้ง, รัน container คนแรก, คำสั่งพื้นฐาน | ✅ |
| **2** | [[Docker Dockerfile]] | เขียน Dockerfile เอง, build image ของตัวเอง, layer/cache, multi-stage build | ✅ |

## สรุปสั้น ๆ ก่อนเริ่ม — Docker คืออะไรในประโยคเดียว

> **Docker คือกล่องที่ห่อโปรแกรมพร้อมทุกอย่างที่มันต้องการไว้ในกล่องเดียว แล้วเอากล่องนั้นไปรันที่ไหนก็ได้ ได้ผลเหมือนกันเป๊ะ**

ปัญหาที่มันแก้คือประโยคคลาสสิกที่ทุกคนเคยได้ยิน: **"ที่เครื่องผมมันรันได้นะ"** (works on my machine) — เพราะเครื่องของแต่ละคนมี OS, เวอร์ชันภาษาโปรแกรม, library ติดตั้งไม่เหมือนกัน Docker ตัดปัญหานี้โดยห่อทุกอย่างที่โปรแกรมต้องการไว้ในกล่องเดียวกัน ไม่ว่าจะรันที่เครื่อง dev, เครื่องเพื่อนร่วมทีม, หรือ server จริง ก็ได้สภาพแวดล้อมเดียวกันทุกครั้ง

---

## กฎรวมที่จำไว้ได้เลย

1. **Image คือพิมพ์เขียว, Container คือของจริงที่รันอยู่** — เหมือนคลาสกับ instance ในการเขียนโปรแกรม image ตัวเดียวสร้าง container ได้หลายตัวพร้อมกัน
2. **Container หายข้อมูลเมื่อถูกลบ** เว้นแต่จะตั้งใจเก็บผ่าน volume — อย่าเก็บข้อมูลสำคัญไว้ในตัว container เฉย ๆ
3. **Dockerfile คือสูตรอาหาร, image คืออาหารที่ทำเสร็จแล้ว** — เขียน Dockerfile ครั้งเดียว build ได้ image ซ้ำ ๆ เหมือนเดิมทุกครั้ง
4. **Layer ที่ไม่เปลี่ยน ถูกใช้ซ้ำ (cache)** — เรียง Dockerfile ให้ของที่เปลี่ยนบ่อยอยู่ล่างสุด จะ build เร็วขึ้นมาก
